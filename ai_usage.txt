# Тиждень 9: багатопотоковість, цикли подій і корутини

Лекція 9.1 про потоки (threads), лекція 9.2 про цикл подій (event loop) та корутини. Наприкінці обидві зводяться до тактики, яку ви використовуєте в проєкті.

## Лекція 9.1: Multithreading

**Процес і потік.** Процес — це запущена програма. ОС дає йому власний віртуальний адресний простір, тому та сама адреса в двох процесах зазвичай означає різні байти. Один потік має один вказівник інструкцій, один стек і один набір регістрів.

**Навіщо другий потік.** Причин дві:
1. Якщо один потік і обробляє події, і рахує, вікно не перемальовується й ОС вважає його «not responding». Другий потік рахує, перший відповідає на події.
2. Один потік працює лише на одному ядрі, тож для шести ядер потрібно шість потоків.

**Що спільне, а що своє.** Потоки одного процесу спільно мають адресний простір (код, глобальні змінні, купу), відкриті файли та id процесу. Власне в кожного потоку: стек, регістри, вказівник інструкцій, id потоку та `thread_local`-змінні. У прикладі з лекції одна глобальна змінна має ту саму адресу в усіх потоків, а локальні лежать на трьох різних стеках.

**Як це в Linux.** Новий потік і новий процес створюються системним викликом `clone`, а прапори визначають, що спільне. `CLONE_VM` означає ту саму пам'ять (`fork` її копіює), `CLONE_THREAD` означає ту саму групу потоків. `gettid()` повертає id задачі, `getpid()` повертає id групи, тобто id першого потоку.

**Гонка даних (lost update).** `x = x + 1` складається з трьох кроків: `load`, `add`, `store`. Між кроками може виконатися інший потік. Якщо обидва потоки прочитали 0, обидва запишуть 1, і з двох інкрементів «виживе» один. Відповідь на питання з лекції: при `x = 0` і двох інкрементах `x` може бути 1 або 2.

**Mutex.** Він дає дві речі:
- *взаємне виключення*: між `lock` і `unlock` перебуває лише один потік, решта чекає;
- *впорядкування*: те, що потік записав до `unlock`, наступний потік бачить після свого `lock`.

Перевірка «ресурс вільний?» і «захопити його» має бути одним неподільним кроком. Та сама перевірка зі звичайним `bool` дає ту саму гонку. У C++ для цього є `std::lock_guard`, який розблоковує мьютекс на закритті дужки.

**Вартість потоків.** Кожен стек резервує 8 MiB адрес, але фізична пам'ять видається по мірі використання. У прикладі 10 000 потоків дали 79 GiB адрес і лише 85 MiB реальної пам'яті. Потік, що чекає, не споживає CPU, але кожне пробудження коштує перемикання контексту. Схема «потік на клієнта» означає 10 000 стеків, майже всі в очікуванні мережі.

**Потоки в мовах:**
- До C++11 потоки були бібліотечною справою з `#ifdef`: `CreateThread` на Windows, `pthread_create` на Linux. С++98 не мав правил про одночасний запис у пам'ять.
- C++11 додав `std::thread`, `std::mutex`, `std::atomic` і модель пам'яті. Ланцюжок викликів такий: ваш код → libstdc++ → `pthread_create` → `clone3`. Це той самий шов, що й LLVM: один інтерфейс над різними ОС, як LLVM IR над процесорами.
- **GIL у Python.** Це один замок навколо інтерпретатора, тому Python-код виконує лише один потік. Потоки допомагають під час очікування I/O або в C-коді, що відпускає GIL. На прикладі з лекції два потоки дали 0.19 с проти 0.20 с, тобто виграшу немає. Зі збіркою без GIL (PEP 703, `3.14t`) час упав з 0.17 до 0.09 с.

**Живий приклад гонки** (два потоки по мільйону інкрементів):

| Варіант | Результат | Час |
|---|---|---|
| без замка, `-O0` | кожного разу інше неправильне число | 2 мс |
| mutex | 2 000 000 | 86 мс |
| atomic `fetch_add` | 2 000 000 | 41 мс |

Mutex правильний, але приблизно у 40 разів повільніший. Atomic правильний і посередині за швидкістю. На `-O2` цикл без замка перетворився на `+= 1000000` і видав «правильні» 2 000 000. Проте це все одно data race, а отже **undefined behaviour**, а не просто неправильне число.

**`spawn` у вашій мові.** Для `spawn work(7)` модуль має містити:
- декларації `pthread_create` і `pthread_join` (як `printf`, вони є в libc);
- struct для аргументів (`spawn.work.args = {i32}`);
- функцію-обгортку `spawn.work(i8*)`, яка розпаковує struct, викликає `fn.work(n)` і повертає `null`, бо `pthread_create` приймає лише `void*(void*)`;
- у місці виклику: `alloca` для tid і для упакованих аргументів, виклик `pthread_create`, потім `pthread_join`, бо програма чекає потік перед `exit`.

На Windows змінилися б декларації та виклики (`CreateThread`, `WaitForSingleObject`). Структура «struct аргументів + обгортка + створити + дочекатися» залишилася б тією самою.

## Лекція 9.2: Event loops і coroutines

### Event loop

Це один потік і черга. Хтось постить задачу (обробник кліку, відкладена задача, робочий потік), а цикл бере її з початку черги, викликає `work()`, потім `callback(result)`.
- `post(work, callback, delay)` означає «зроби це пізніше й повідом мене результатом».
- Дві задачі ніколи не виконуються одночасно, бо їх виконує один потік.
- Готові задачі йдуть у порядку постингу, відкладена чекає свого часу.
- У реалізації це `deque` і `while queue`. Якщо задача зарано, вона йде в кінець черги.

**Задача постить наступну задачу.** `check` постить сама себе. Це не рекурсія, а новий елемент у кінці черги, тому стек не росте і після 100 перевірок глибина та сама (`run → check`).

**Головна небезпека.** Одна повільна задача блокує всіх. Поки вона не повернеться, немає ні тіків, ні кліків, ні перемальовування. Тому правило таке: задача на циклі лише запускає роботу деінде й одразу повертається. Копіювання 2 GB на UI-циклі заморозить вікно.

**Складність дебагу.** У traceback видно, що `run` викликав задачу, але не видно, хто і коли її запостив.

**Відповіді на питання з лекції:**
- Дві задачі одного циклу пишуть одну змінну: mutex не потрібен, бо вони не паралельні.
- Задача і потік завантаження: так, потрібен, бо це вже два потоки.

### Coroutines

**Проблема.** Генератор на окремому потоці — марнотратство: потік ядра, 8 MiB стека, mutex і condition variable з обох боків. Потрібно менше: місце, де локальні змінні переживають між запитами, і точка, з якої продовжувати.

**`co_yield` у C++20.** `squares(3)` створює frame і одразу зупиняється, нічого не обчисливши. Кожен `next()` виконується до наступного `co_yield`. Четвертий `next()` доходить до `co_return`, і `done()` стає true. Frame займає 40 байт у купі.

**Де чекають локальні змінні: два підходи**

| | Stackful | Stackless |
|---|---|---|
| Де живе | власний стек | frame-об'єкт (зазвичай на купі) |
| Що зберігається | SP, IP, регістри | лише локальні змінні самої корутини + індекс точки продовження |
| Хто може робити yield | будь-яка функція на цьому стеку | лише тіло самої корутини |
| Приклад у C | `ucontext` (`swapcontext`) | struct + `switch` по `state` |

- **Stackful.** `makecontext` вручну будує перший контекст: SP вказує на новий стек, IP на `squares`. Вкладена `square_of` теж може зробити `yield`.
- **Stackless.** Змінні, що живуть між `co_yield`, стають полями struct (як захоплення лямбди з лекції 7.2). `co_yield` перетворюється на «запам'ятати точку й повернутися», а відновлення — це перехід у `switch` до потрібного `case`. У прикладі frame займає 16 байт без власного стека.
- **Що пише clang.** Одна функція перетворюється на три: `squares` лише створює frame, а `.resume` і `.destroy` його обробляють. Індекс продовження зберігається в frame. На `-O2` виділення зникло, бо frame не втік за межі `main`.

**Хто як робить:**
- C++20: `co_yield`, `co_await`, `co_return`, stackless.
- Python: `yield`, `async def`, stackless, frame-об'єкт.
- Kotlin: `suspend fun`, stackless, state machine із continuation-об'єктом.
- Lua: `coroutine.create(f)`, stackful, будь-яка функція може робити yield.
- Go: `go f()`, goroutine зі своїм невеликим стеком, що росте, планується рантаймом Go.

Stackless потребує позначки, бо компілятор мусить знати, які функції розрізати. Stackful позначки не потребує, але платить стеком.

**Важливе обмеження.** Ядро планує потоки, а не корутини. Корутини самі по собі не дають паралелізму: на одному потоці працює одна. Блокувальний системний виклик (`read`, `sleep`) зупиняє всі корутини цього потоку, як повільна задача зупинила цикл.

**Відповіді на питання:**
- Stackful зберігає цілий стек викликів, тому дозволяє `yield` з глибоких вкладених викликів. Stackless цього не вміє.
- Перший контекст береться: у stackful із `makecontext` (вручну), у stackless із frame, який будує сама функція при виклику.
- `squares(3)` створює 0 потоків і 1 frame.

### Загальна тактика

На лекції весь цей матеріал зведено до одного шаблону: нова синтаксична можливість означає структуру даних, яку додає компілятор, і звичайні виклики в IR.

| Можливість | Що додає компілятор | Виклики в IR |
|---|---|---|
| member function | record структури | `Point_shift(&p, 2)` |
| lambda | struct, поле на кожне захоплення | її виклик |
| template | копія дерева і кеш | `add_i64_i32` |
| `spawn` | struct для аргументів і обгортка | `pthread_create`, `pthread_join` |
| coroutine | frame з індексом | `resume`, `destroy` |

Оптимізатор робить зворотне: прибирає те, що ніхто не читає і не викликає.

  - Рефлексія: запис, який компілятор уже має, використовується під час компіляції (`print`) і під час виконання (Python, Java, Go).
  - Серіалізація (`print_json`): та сама обхідна логіка, одна згенерована функція на тип.
- **Практика 8:** callable-об'єкти (`obj(args)` стає `obj.call(args)` у checker), лямбди з capture list (стають struct + `call` + змінна), `--ast-checked`. Додатково `[mut n]`.

## Наскрізна схема курсу
Кожна нова можливість мови йде за одним шаблоном: **новий синтаксис → структура даних у checker → звичайні виклики в IR**.

| Можливість | Що її моделює |
|---|---|
| вираз | дерево, обхід знизу вгору |
| тип | `node.type`, `sext`, `icmp` |
| scope | стек фреймів у checker |
| `if`/`while` | basic blocks, `cbranch`, `phi` |
| функція | `declare` потім `define`, фрейм, `ret` |
| метод | функція з `this`-вказівником |
| лямбда | struct + `call` + змінна |
| шаблон | копія дерева + кеш |
| concept | lookup у записі структури |
| `spawn` (тиждень 9) | struct аргументів + обгортка + `pthread_create` |

Також кожна помилка ловиться на найранішій фазі, яка її бачить: lexer, parser, semantic pass, builder, `llc`, runtime.

## Task 1: невикористані змінні (1.5 бала)

**Що є використанням (read):** ініціалізатор, права частина `:=`, умова, аргумент, `print`, `exit`, початок ланцюжка `p.x`, об'єкт member-виклику `p.sum()`, capture `[k]`, callable-об'єкт `c(5)`.

**Виняток:** якщо в ініціалізаторі (або у правій частині присвоєння) є виклик або `read()`, декларація залишається. Функція може друкувати, тому такі випадки лишаються до додаткового завдання.

1. Visitor рахує читання **на кожну декларацію**, а не за іменем. Ключ `id(decl)`, бо дві змінні `x` це два різні ключі. Для цього checker має заповнювати поле `decl` на кожному вузлі змінної.

3. Якщо щось видалено, візитор запускається знову. Зупинка, коли раунд нічого не видалив.

**В зоні проходу:** top level, блоки `if` і `while`, тіла функцій, member functions і лямбд.

```python
# ---------------- Practice 9: --remove-unused ----------------

def has_effect(n, effects=None):
    """May evaluating n be observed? read(), or a call.
    effects=None: every call counts (Task 1). Otherwise only calls of fns in `effects`."""
    if isinstance(n, ReadNode):
        return True
    if isinstance(n, (CallNode, MemberCallNode)):
        sugar = getattr(n, "sugar", None)
        if sugar is not None:
            return has_effect(sugar, effects)
        if effects is None or n.fn in effects:
            return True
    return any(has_effect(c, effects) for c in n.children())


class UseCounter:
    def __init__(self, effects=None):
        self.effects = effects
        self.reads = {}          # id(DeclNode) -> number of reads
        self.decls = {}          # id -> node (keeps the ids valid during the round)
        self.calls = {}          # id(global FnNode) -> number of calls
        self.live_lambdas = set()  # id(lambda struct) of lambdas reached

    def read(self, decl):
        if isinstance(decl, DeclNode):      # params, fields (ThisNode) are never removed
            self.reads[id(decl)] = self.reads.get(id(decl), 0) + 1
            self.decls[id(decl)] = decl

    def walk(self, n):
        if isinstance(n, DeclNode):
            self.reads.setdefault(id(n), 0)
            self.decls[id(n)] = n
            if any(has_effect(e, self.effects) for e in n.inits):
                self.read(n)                # kept: the value may be observed
        elif isinstance(n, AssignNode):     # the target is not a read ...
            if has_effect(n.value, self.effects):
                self.read(n.decl)           # ... unless the value may print
        elif isinstance(n, (VarNode, MemberNode)):
            self.read(getattr(n, "decl", None))
        elif isinstance(n, (CallNode, MemberCallNode)):
            sugar = getattr(n, "sugar", None)
            if sugar is not None:           # callable object: a call of its `call`
                self.walk(sugar)
                return
            if isinstance(n, CallNode) and n.this is None:
                self.calls[id(n.fn)] = self.calls.get(id(n.fn), 0) + 1
        elif isinstance(n, LambdaNode):     # a lambda stays; its captures are reads
            self.live_lambdas.add(id(n.struct))
            for init in n.decl.inits:
                self.walk(init)
            for fn in n.struct.fns:
                self.walk(fn.body)
            return
        for c in n.children():
            self.walk(c)


class Pruner:
    def __init__(self, dead_decls, dead_fns):
        self.dead_decls, self.dead_fns, self.removed = dead_decls, dead_fns, 0

    def is_dead(self, s):
        if isinstance(s, DeclNode):
            return id(s) in self.dead_decls
        if isinstance(s, AssignNode):
            return id(s.decl) in self.dead_decls
        return False

    def prune(self, n):
        if isinstance(n, ProgramNode):
            kept = [f for f in n.functions if id(f) not in self.dead_fns]
            self.removed += len(n.functions) - len(kept)
            n.functions = kept
        if isinstance(n, (ProgramNode, BlockNode)):
            kept = [s for s in n.statements if not self.is_dead(s)]   # rebuild, not delete
            self.removed += len(n.statements) - len(kept)
            n.statements = kept
        if isinstance(n, LambdaNode):
            for fn in n.struct.fns:
                self.prune(fn.body)
            return
        for c in n.children():
            self.prune(c)


def remove_unused(tree, use_effects=False):
    rounds = 0
    while True:
        rounds += 1
        effects = effectful_fns(tree) if use_effects else None
        counter = UseCounter(effects)
        counter.walk(tree)
        dead_decls = {i for i, k in counter.reads.items() if k == 0}
        dead_fns = {id(f) for f in tree.functions if counter.calls.get(id(f), 0) == 0}
        pruner = Pruner(dead_decls, dead_fns)
        pruner.prune(tree)
        if os.environ.get("OPT_TRACE"):
            print(f"round {rounds}: removed {pruner.removed}", file=sys.stderr)
        if pruner.removed == 0:
            tree.lambda_structs = [s for s in tree.lambda_structs
                                   if id(s) in counter.live_lambdas]
            return tree
```

```python
def collect_callees(n, out):
    if isinstance(n, LambdaNode):
        return                               # declaring a lambda calls nothing
    if isinstance(n, (CallNode, MemberCallNode)):
        sugar = getattr(n, "sugar", None)
        if sugar is not None:
            collect_callees(sugar, out)
            return
        out.add(n.fn)
    for c in n.children():
        collect_callees(c, out)

def own_effect(n):
    if isinstance(n, LambdaNode):
        return False
    if isinstance(n, (PrintNode, ReadNode, WhileNode)):
        return True
    return any(own_effect(c) for c in n.children())

def effectful_fns(tree):
    fns = list(tree.functions)
    for st in tree.structs + tree.lambda_structs:
        fns += st.fns
    callees, eff = {}, set()
    for f in fns:
        out = set()
        collect_callees(f.body, out)
        callees[f] = out
        if (isinstance(f, MemberFnNode) and f.mutating) or own_effect(f.body):
            eff.add(f)

    def recursive(f):                        # f can reach itself: it may not return
        seen, stack = set(), list(callees[f])
        while stack:
            g = stack.pop()
            if g is f:
                return True
            if g in seen or g not in callees:
                continue
            seen.add(g)
            stack.extend(callees[g])
        return False

    eff |= {f for f in fns if recursive(f)}
    changed = True
    while changed:                           # fixpoint: callers of effectful fns
        changed = False
        for f in fns:
            if f not in eff and callees[f] & eff:
                eff.add(f)
                changed = True
    return eff
```

# Вступ до Practice 9: що це і навіщо

## Що таке оптимізація

Оптимізація змінює, **як** програма працює, але не змінює, **що** вона робить. «Що вона робить» — це лише те, що бачить зовнішній спостерігач: надруковані рядки, прочитаний ввід і exit-значення. Змінні, функції та порядок обчислень до цього не належать, тому компілятор може їх змінювати. У C++ це зветься **as-if rule**: можна робити будь-що, поки спостережувана поведінка та сама.

## Приклад із clang
```c
int main(void) { int unused = 42; return 0; }
```
- На `-O0` змінна отримує `alloca` і `store`.
- На `-O1` лишається тільки `ret i32 0`, бо ніхто змінну не читає.

Програма однаково повертає 0. Це і буде твоя задача, тільки на рівні дерева.

## Де працюють оптимізації
Є три рівні:

| Рівень | Приклад | Що знає |
|---|---|---|
| **дерево** (наше) | `--remove-unused` | імена, scope, цілі функції |
| **IR** | `opt -passes=dce`, `globaldce` | інструкції |
| **машинний код** | peephole | регістри |

Цього тижня прохід один, на дереві, після checker і перед кодогеном. Функція на дереві — це один вузол, тому її видалення прибирає тіло з усіма деклараціями та викликами за один раз. На IR це було б набагато складніше.

## Чому прохід ітерується
Видалення одного робить інше непотрібним. Для `y{x}`, який ніхто не читає, `x` читає лише `y`, що зникає. Тому прохід повторюється, поки раунд нічого не видалив. Цикл завершується, бо кожен «непорожній» раунд зменшує кількість декларацій або функцій, а їх скінченна кількість.

## Правило «сумніваєшся — залишай»
- Залишив зайве — просто повільніше.
- Видалив потрібне — **неправильний компілятор**.

Декларація, у чиєму значенні є виклик, залишається: функція може друкувати. Перевірка механічна: програма має друкувати те саме з прапорцем і без нього.

# Task 1: невикористані змінні

## Що треба зробити
Знайти декларації, які ніхто не читає, і видалити їх разом з усіма присвоєннями до них. Програма має надрукувати те саме. Це перший прохід, який **прибирає** частину програми, а не лише перевіряє чи перекладає її.

## Що вважається використанням (read)
Змінна прочитана, коли її значення десь потрібне:
- в ініціалізаторі (`i32 y{x}`) і в правій частині `:=`;
- в умові `if`/`while`, в аргументі виклику, в `print`, в `exit`;
- на початку ланцюжка `p.x` та як об'єкт виклику `p.sum()`;
- в capture list `[k]`;
- як callable-об'єкт у `c(5)`.

**Присвоєння не є використанням.** Якщо `y := 5` стоїть на змінній, яку ніхто не читає, вона така ж мертва, як її декларація. Тому з декларацією зникають усі присвоєння до неї.

## Виняток: виклики та `read()`
Функція може друкувати чи читати ввід, тому видалення виклику може змінити поведінку. Правило для цього завдання:
- декларація, в ініціалізаторі якої є виклик або `read()`, **лишається**, навіть якщо її не читають;
- присвоєння зі значенням, що містить виклик або `read()`, теж лишається разом з декларацією своєї змінної.

Розумніше правило («виклик без ефекту можна прибрати») це додаткове завдання (+1).

## Алгоритм у три кроки
1. **Підрахунок.** Один візитор обходить усе дерево і для кожної **декларації** (а не для кожного імені) рахує читання, що на неї вказують. Checker уже розв'язав кожне ім'я до декларації (`node.decl`), тож тут ніякої нової логіки scope не потрібно.
2. **Видалення.** Кожна декларація з нулем читань зникає з блока разом із присвоєннями до неї.
3. **Повтор.** Якщо щось видалили, рахуємо знову: читання, що жили всередині видалених ініціалізаторів, зникли, і ще якісь декларації могли стати нульовими. Зупинка, коли раунд нічого не видалив.

## Що в зоні проходу
- **Входять:** top level, блоки `if`/`while`, тіла функцій, member functions і лямбд.
- **Не чіпаємо:** параметри (їх передають викликачі незалежно від того, читає тіло їх чи ні), поля структур і самі лямбди.

## Розбір warm-up 2

| Раунд | Декларація | Читань | Дія |
|---|---|---|---|
| 1 | `r` | 1 (`exit r`) | лишається |
| 1 | зовнішній `x` | 0 | **видаляється** (`r := x` читає внутрішній) |
| 1 | внутрішній `x` | 1 (`r := x`) | лишається |

## Типові пастки
- **Рахунок за іменем** замість за декларацією.
- **Зарахувати target присвоєння як читання.** Тоді `y := 5` тримає `y` живою.
- **Видалити декларацію, але забути присвоєння.** Кодоген потім не знайде слот.
- **Видалити параметри.**
- **`if` із порожнім блоком після видалення** лишається, бо його умова все одно обчислюється. Кодоген має спокійно приймати порожній блок.
- **Прапорці в фіксованих позиціях.** Вони можуть стояти будь-де.
- **Запуск до checker.** Невалідна програма не має потрапляти в оптимізацію.

## Відомий ліміт
`k := k + 1`, де `k` більше ніхто не читає, лишається, бо права частина читає `k`. Це обмеження підрахунку читань, а не помилка. Про це треба написати в README.

## Що вже є в твоєму коді

- Capture `[k]` читає `k` через `VarNode` у `inits` closure-декларації.
- Декларація лямбди (`node.decl`) теж `DeclNode`, її читають виклики `add_k(...)`.

## Код

```python
# ---------------- Practice 9: --remove-unused ----------------

def has_call_or_read(n):
    """Чи може обчислення n бути спостережуваним: read() або будь-який виклик."""
    if isinstance(n, (ReadNode, CallNode, MemberCallNode)):
        return True
    return any(has_call_or_read(c) for c in n.children())


class UseCounter:
    def __init__(self):
        self.reads = {}    # id(DeclNode) -> кількість читань
        self.decls = {}    # id(DeclNode) -> сам вузол (для друку)

    def read(self, decl):
        if isinstance(decl, DeclNode):      # параметри та поля (ThisNode) ігноруємо
            self.reads[id(decl)] = self.reads.get(id(decl), 0) + 1

    def walk(self, n):
        if isinstance(n, DeclNode):
            self.decls[id(n)] = n
            self.reads.setdefault(id(n), 0)
            if any(has_call_or_read(e) for e in n.inits):
                self.read(n)                # лишається: значення може друкувати
        elif isinstance(n, AssignNode):
            if has_call_or_read(n.value):
                self.read(n.decl)           # ціль — не читання, крім випадку з ефектом
        elif isinstance(n, (VarNode, MemberNode)):
            self.read(n.decl)
            return
        elif isinstance(n, LambdaNode):
            self.walk(n.decl)               # inits декларації = читання захоплених змінних
            self.walk(n.body)
            return
        sugar = getattr(n, "sugar", None)
        if sugar is not None:               # виклик callable-об'єкта
            self.walk(sugar)
            return
        for c in n.children():
            self.walk(c)

    def report(self):
        for d in sorted(self.decls.values(), key=lambda d: (d.line, d.col)):
            print(f"line {d.line}: {d.name} reads={self.reads[id(d)]}")
```

## Код 1: `Pruner` і цикл
Вставити одразу після класу `UseCounter` (перед `class CodeGen`).

```python
class Pruner:
    def __init__(self, dead):
        self.dead = dead
        self.removed = 0

    def is_dead(self, s):
        if isinstance(s, DeclNode):
            return id(s) in self.dead
        if isinstance(s, AssignNode):
            return id(s.decl) in self.dead
        return False

    def prune(self, n):
        if isinstance(n, (ProgramNode, BlockNode)):
            kept = [s for s in n.statements if not self.is_dead(s)]
            self.removed += len(n.statements) - len(kept)
            n.statements = kept
        for c in n.children():
            self.prune(c)


def remove_unused(tree):
    rounds = 0
    while True:
        rounds += 1
        counter = UseCounter()
        counter.walk(tree)
        dead = {i for i, k in counter.reads.items() if k == 0}
        pruner = Pruner(dead)
        pruner.prune(tree)
        if os.environ.get("OPT_TRACE"):
            print(f"round {rounds}: removed {pruner.removed}", file=sys.stderr)
        if pruner.removed == 0:
            return tree
```

## Що і чому зроблено

**`Pruner`.** Обходить дерево через `children()` і в кожному `ProgramNode` та `BlockNode` **перебудовує** список `statements` без мертвих елементів. Список ми не змінюємо на місці: видалення з колекції під час ітерації пропускає елементи. Мертвим вважається:
- `DeclNode`, чий `id` у множині `dead`;
- `AssignNode`, чий `decl` у `dead`. Це «присвоєння зникають разом з декларацією», інакше кодоген знайде ім'я без слота.

Параметри й поля сюди не потрапляють: `read()` у `UseCounter` рахує лише `DeclNode`, а присвоєння з `decl`, що не в `dead`, не чіпається.

**Лямбди не видаляються.** Їхній `decl` потрапляє в таблицю з нулем читань, якщо замикання ніхто не викликає, але `LambdaNode` не є `DeclNode`, і `is_dead` його пропускає. Тіло лямбди в `children()` теж доступне і прунінг дійде до його блоків. Це те саме `BlockNode`-тіло, яке використовує `call` у struct, тож зміни видно і в згенерованому коді.

**Цикл.** Кожен раунд заново рахує читання на уже зменшеному дереві і зупиняється, коли `pruner.removed == 0`. `OPT_TRACE=1` друкує кількість видалених на раунд у stderr.

**Чому прохід після `--ast`.** Умова завдання: `--ast` лишається деревом парсера, а `--ast-checked` показує те, що піде в кодоген. Тому видалення стоїть після блоку `--ast` і до `--ast-checked`. Для звичайної компіляції цей рядок теж виконується, і кодоген отримує вже прорідженене дерево.

**Прапорці в будь-якому порядку.** Цикл збирає прапорці окремо від шляхів, тому `compiler.py in.txt --remove-unused out.ll` теж працює.

# Крок 3: невикористані функції (Task 2)

Той самий підхід, що й для змінних, тільки одиницею підрахунку стає глобальна функція, а лічильником кількість її викликів.

## Що змінюється

**У `UseCounter`.** Додаємо словник `calls`: `id(FnNode)` → кількість викликів. Виклик `CallNode` рахується, коли це глобальна функція (`this is None`), а не member function. Рахується він де завгодно: у statements, в інших функціях, у member functions, у тілах лямбд. Це працює без додаткових зусиль, бо обхід і так проходить усе дерево.

**У `Pruner`.** Крім декларацій, прибирає з `ProgramNode.functions` функції з нульовою кількістю викликів. Видалений вузол `FnNode` забирає з собою все тіло.

**У циклі.** Множина мертвих функцій обчислюється в тому ж раунді, що й мертві змінні. Нового циклу не треба.

## Код

Заміни цілком `UseCounter`, `Pruner` і `remove_unused` (поряд з ними лишається `has_call_or_read` без змін):

```python
class UseCounter:
    def __init__(self):
        self.reads = {}
        self.decls = {}
        self.calls = {}

    def read(self, decl):
        if isinstance(decl, DeclNode):
            self.reads[id(decl)] = self.reads.get(id(decl), 0) + 1

    def walk(self, n):
        if isinstance(n, DeclNode):
            self.decls[id(n)] = n
            self.reads.setdefault(id(n), 0)
            if any(has_call_or_read(e) for e in n.inits):
                self.read(n)
        elif isinstance(n, AssignNode):
            if has_call_or_read(n.value):
                self.read(n.decl)
        elif isinstance(n, (VarNode, MemberNode)):
            self.read(n.decl)
            return
        elif isinstance(n, LambdaNode):
            self.walk(n.decl)
            self.walk(n.body)
            return
        sugar = getattr(n, "sugar", None)
        if sugar is not None:
            self.walk(sugar)
            return
        if isinstance(n, CallNode) and n.this is None:
            self.calls[id(n.fn)] = self.calls.get(id(n.fn), 0) + 1
        for c in n.children():
            self.walk(c)

    def report(self):
        for d in sorted(self.decls.values(), key=lambda d: (d.line, d.col)):
            print(f"line {d.line}: {d.name} reads={self.reads[id(d)]}")


class Pruner:
    def __init__(self, dead, dead_fns):
        self.dead = dead
        self.dead_fns = dead_fns
        self.removed = 0

    def is_dead(self, s):
        if isinstance(s, DeclNode):
            return id(s) in self.dead
        if isinstance(s, AssignNode):
            return id(s.decl) in self.dead
        return False

    def prune(self, n):
        if isinstance(n, ProgramNode):
            kept = [f for f in n.functions if id(f) not in self.dead_fns]
            self.removed += len(n.functions) - len(kept)
            n.functions = kept
        if isinstance(n, (ProgramNode, BlockNode)):
            kept = [s for s in n.statements if not self.is_dead(s)]
            self.removed += len(n.statements) - len(kept)
            n.statements = kept
        for c in n.children():
            self.prune(c)


def remove_unused(tree):
    rounds = 0
    while True:
        rounds += 1
        counter = UseCounter()
        counter.walk(tree)
        dead = {i for i, k in counter.reads.items() if k == 0}
        dead_fns = {id(f) for f in tree.functions if counter.calls.get(id(f), 0) == 0}
        pruner = Pruner(dead, dead_fns)
        pruner.prune(tree)
        if os.environ.get("OPT_TRACE"):
            print(f"round {rounds}: removed {pruner.removed}", file=sys.stderr)
        if pruner.removed == 0:
            return tree
```

## Чому це працює

- **`n.this is None`** відрізняє глобальний виклик від виклику member function усередині struct. Для member function `this` це `ThisNode`, а `fn` це `MemberFnNode`, яку ми не видаляємо. Перевірка стоїть **після** блоку `sugar`, бо у `CallNode` з `sugar` (callable-об'єкт) атрибута `this` немає взагалі.
- **Виклики в мертвій функції теж рахуються** у раунді, коли вона ще існує. Тому ланцюжок видаляється по одній функції за раунд, як в умові: `unused` у раунді 1, `helper` у раунді 2, `twice` лишається.
- **Рекурсивна функція** викликає саму себе, тож її лічильник ніколи не стане нулем. Так само дві функції, що викликають лише одна одну. Це відомий ліміт підрахунку (ніби refcounting не звільнить цикл), про нього треба написати в README.
- **Лямбди** обходяться через `n.body`, тож виклики глобальних функцій у тілі лямбди теж рахуються.

**3. `Pruner`:** новий конструктор і видалення функцій на початку `prune`.
```python
class Pruner:
    def __init__(self, dead, dead_fns):
        self.dead = dead
        self.dead_fns = dead_fns
        self.removed = 0

    def is_dead(self, s):
        if isinstance(s, DeclNode):
            return id(s) in self.dead
        if isinstance(s, AssignNode):
            return id(s.decl) in self.dead
        return False

    def prune(self, n):
        if isinstance(n, ProgramNode):
            kept = [f for f in n.functions if id(f) not in self.dead_fns]
            self.removed += len(n.functions) - len(kept)
            n.functions = kept
        if isinstance(n, (ProgramNode, BlockNode)):
            kept = [s for s in n.statements if not self.is_dead(s)]
            self.removed += len(n.statements) - len(kept)
            n.statements = kept
        for c in n.children():
            self.prune(c)
```

**4. `remove_unused`:** обчисли мертві функції і передай їх у `Pruner`.
```python
def remove_unused(tree):
    rounds = 0
    while True:
        rounds += 1
        counter = UseCounter()
        counter.walk(tree)
        dead = {i for i, k in counter.reads.items() if k == 0}
        dead_fns = {id(f) for f in tree.functions if counter.calls.get(id(f), 0) == 0}
        pruner = Pruner(dead, dead_fns)
        pruner.prune(tree)
        if os.environ.get("OPT_TRACE"):
            print(f"round {rounds}: removed {pruner.removed}", file=sys.stderr)
        if pruner.removed == 0:
            return tree
```

## Чому це працює

- **Лічильник викликів.** `n.this is None` відрізняє глобальний виклик від виклику member function усередині struct. Для member function `this` це `ThisNode`, і ми її не видаляємо. Перевірка стоїть після блоку `sugar`, бо у виклику callable-об'єкта атрибута `this` немає. Такий `CallNode` ми вже обробили вище і вийшли через `return`.
- **Виклики рахуються де завгодно:** у statements, в інших функціях, у member functions, у тілах лямбд. Обхід і так проходить усе дерево, тож додаткової логіки не треба.
- **Каскад.** У раунді 1 функція `unused` має 0 викликів і видаляється, але виклик `helper(1)` у її тілі ще порахований у цьому раунді. Тому `helper` мертвий лише в раунді 2, а `twice` у раунді 3 лишається. Саме так виходить три раунди, як в умові.
- **Видалення цілого вузла.** Коли `FnNode` прибрано зі списку, `prune` вже не заходить у його тіло (`children()` бере оновлений список), тож жодних зайвих рахунків.
- **Цикли.** Рекурсивна функція викликає саму себе, і лічильник ніколи не стає нулем. Те саме для двох функцій, що викликають одна одну. Це ліміт підрахунку, його треба згадати в README, як і `k := k + 1`.

# Task 2: невикористані функції

## Ідея
Це та сама схема, що в Task 1, на рівень вище. Одиницею підрахунку тепер є **глобальна функція**, а лічильником **кількість її викликів**. Нуль викликів означає, що функцію видаляють разом із тілом, а всередині цього тіла зникають усі декларації та виклики. Нового циклу не потрібно: той самий раунд рахує і читання змінних, і виклики функцій.

## Що саме рахуємо і що видаляємо
- **Виклики рахуємо де завгодно:** у statements верхнього рівня, в інших функціях, у member functions, у тілах лямбд.
- **Видаляємо лише глобальні функції.** Member functions і лямбди лишаються, навіть якщо їх ніхто не викликає.
- **Виклик member function чи callable-об'єкта не є викликом глобальної функції**, тож у лічильник вони не йдуть.

## Розбір прикладу з завдання
```
fn twice(a)  { r = a + a; exit r }
fn helper(a) { exit twice(a) }
fn unused()  { exit helper(1) }
exit twice(2)
```

| Раунд | Виклики | Дія |
|---|---|---|
| 1 | `twice`: 2 (з `helper` і з `exit`), `helper`: 1 (з `unused`), `unused`: 0 | видаляється `unused` |
| 2 | `twice`: 2, `helper`: 0 (його єдиний виклик зник разом з `unused`) | видаляється `helper` |
| 3 | `twice`: 1 (з `exit`) | нічого, зупинка |

Тому раундів три. Результат 4 до і після, а в `.ll` лишаються лише `fn.twice` і `main`.

Зверни увагу на причину каскаду: у раунді 1 `helper` ще виглядає викликаним, бо `unused` у цьому раунді ще існує. Саме тому лічити треба на кожному раунді заново, а не один раз.

## Ліміт підрахунку
- Дві функції, що викликають тільки одна одну, ніколи не дійдуть до нуля, і лишаються.
- Те саме з рекурсивною функцією: вона викликає себе, тож лічильник ≥ 1, навіть якщо ззовні її ніхто не викликає.

Підрахунок не бачить циклів, як і reference counting. Це варто згадати в README поруч із `k := k + 1`.

## Три місця, де цей таск може зламатися
1. **Не відрізнити виклики.** У твоєму дереві `CallNode` буває трьох видів: глобальна функція (`this is None`), member function всередині struct (`this` це `ThisNode`) і callable-об'єкт (є `sugar`, а `this` взагалі немає). Рахувати треба лише перший вид, інакше або не порахуєш виклик, або впадеш на відсутньому атрибуті.
2. **Лямбда всередині видаленої функції.** Тіла лямбд живуть не лише в дереві, а й у плоскому списку `tree.lambda_structs`, який кодоген теж обходить. Якщо видалити функцію, у якій оголошено лямбду, її struct і `call` лишаться в цьому списку. Якщо тіло такої лямбди викликало глобальну функцію `g`, яка після каскаду теж зникла, кодоген спробує згенерувати виклик неіснуючої `fn.g` і впаде. У коді, який я давала раніше для цього кроку, цього випадку немає. Лікується фільтрацією `lambda_structs` до лямбд, які ще досяжні з дерева після циклу. Додамо це разом із тестом «лямбда всередині невикористаної функції».
3. **Видалені функції не повинні знову потрапляти в підрахунок.** Прибирати треба зі списку `tree.functions`, а не лише позначати: тоді `children()` більше не веде в їхні тіла.

# Крок 1: рахуємо виклики функцій (без видалення)

Як і в Task 1, спочатку тільки підрахунок. Видалення додамо наступним кроком, коли побачимо, що числа правильні.

## Що змінюємо
Замінюємо цілком клас `UseCounter`. Старого коду там змінено небагато, три місця додано.

```python
class UseCounter:
    def __init__(self):
        self.reads = {}
        self.decls = {}
        self.calls = {}
        self.fn_nodes = {}

    def read(self, decl):
        if isinstance(decl, DeclNode):
            self.reads[id(decl)] = self.reads.get(id(decl), 0) + 1

    def walk(self, n):
        if isinstance(n, FnNode) and not isinstance(n, MemberFnNode):
            self.fn_nodes[id(n)] = n
            self.calls.setdefault(id(n), 0)
        if isinstance(n, DeclNode):
            self.decls[id(n)] = n
            self.reads.setdefault(id(n), 0)
            if any(has_call_or_read(e) for e in n.inits):
                self.read(n)
        elif isinstance(n, AssignNode):
            if has_call_or_read(n.value):
                self.read(n.decl)
        elif isinstance(n, (VarNode, MemberNode)):
            self.read(n.decl)
            return
        elif isinstance(n, LambdaNode):
            self.walk(n.decl)
            self.walk(n.body)
            return
        sugar = getattr(n, "sugar", None)
        if sugar is not None:
            self.walk(sugar)
            return
        if isinstance(n, CallNode) and n.this is None:
            self.calls[id(n.fn)] = self.calls.get(id(n.fn), 0) + 1
        for c in n.children():
            self.walk(c)

    def report(self):
        for d in sorted(self.decls.values(), key=lambda d: (d.line, d.col)):
            print(f"line {d.line}: {d.name} reads={self.reads[id(d)]}")
        for f in sorted(self.fn_nodes.values(), key=lambda f: (f.line, f.col)):
            print(f"line {f.line}: fn {f.name} calls={self.calls[id(f)]}")
```

Pruner і `remove_unused` поки не чіпай.

## Що тут нове і чому

**1. `fn_nodes` і `calls.setdefault` на вході в `FnNode`.** Нам потрібен запис про кожну глобальну функцію навіть з нулем викликів. Якби ми додавали запис лише тоді, коли бачимо виклик, функція без викликів взагалі не потрапила б у таблицю, і ми не змогли б сказати, що вона мертва. Перевірка `not isinstance(n, MemberFnNode)` потрібна, бо `MemberFnNode` успадковується від `FnNode`, а member functions ми не видаляємо.

**2. Підрахунок `CallNode` з `n.this is None`.** У твоєму дереві `CallNode` буває трьох видів:
- глобальна функція: `this` дорівнює `None`, це те, що рахуємо;
- member function усередині struct: `this` це `ThisNode`, не рахуємо;
- callable-об'єкт (`add_k(5)`): має `sugar`, а атрибута `this` у нього взагалі немає.

Третій вид ми відсікаємо раніше блоком `sugar` з `return`, тому до нашого рядка він не доходить і помилки `AttributeError` не буде. Тому порядок важливий: підрахунок стоїть **після** блоку `sugar`.

**3. Звідки береться `n.fn`.** Checker у `visit_call` для кожного розв'язаного виклику ставить `node.fn` на вузол функції. Ми рахуємо по `id(n.fn)`, тобто по самому вузлу, а не за іменем. **4. Виклики рахуються де завгодно, нічого додатково робити не треба.** Обхід і так іде по statements, тілах функцій (через `children()` у `ProgramNode`), member functions (struct → `fns`) і тілах лямбд (через `n.body`).

# Крок 2: видалення функцій і цикл

Змінюємо два місця: `Pruner` і `remove_unused`. `UseCounter` не чіпаємо.

## Код

Заміни `Pruner` цілком:

```python
class Pruner:
    def __init__(self, dead, dead_fns):
        self.dead = dead
        self.dead_fns = dead_fns
        self.removed = 0

    def is_dead(self, s):
        if isinstance(s, DeclNode):
            return id(s) in self.dead
        if isinstance(s, AssignNode):
            return id(s.decl) in self.dead
        return False

    def prune(self, n):
        if isinstance(n, ProgramNode):
            kept = [f for f in n.functions if id(f) not in self.dead_fns]
            self.removed += len(n.functions) - len(kept)
            n.functions = kept
        if isinstance(n, (ProgramNode, BlockNode)):
            kept = [s for s in n.statements if not self.is_dead(s)]
            self.removed += len(n.statements) - len(kept)
            n.statements = kept
        for c in n.children():
            self.prune(c)
```

Заміни `remove_unused` цілком:

```python
def remove_unused(tree):
    rounds = 0
    while True:
        rounds += 1
        counter = UseCounter()
        counter.walk(tree)
        dead = {i for i, k in counter.reads.items() if k == 0}
        dead_fns = {id(f) for f in tree.functions if counter.calls.get(id(f), 0) == 0}
        pruner = Pruner(dead, dead_fns)
        pruner.prune(tree)
        if os.environ.get("OPT_TRACE"):
            print(f"round {rounds}: removed {pruner.removed}", file=sys.stderr)
        if pruner.removed == 0:
            return tree
```

## Що і чому

**`dead_fns`.** Це множина `id` глобальних функцій з нулем викликів. Беремо їх з `tree.functions`, тобто тільки глобальні. Member functions і лямбди туди не потрапляють, як вимагає завдання.

**`calls.get(id(f), 0)`.** Якщо функцію ніхто не викликав, запису в `calls` може не бути, тому `get` з нулем за замовчуванням. Насправді `walk` робить `setdefault` для кожного `FnNode`, але це страхує від випадку, коли функції ще немає в таблиці.

**Видалення функції в `prune`.** Блок для `ProgramNode` перебудовує список `functions` без мертвих. Список не змінюється на місці, а створюється новий. Після цього наступний рядок `for c in n.children()` обходить уже новий список, тож у тіла видалених функцій `prune` не заходить. Це «один зріз»: усе, що було в тілі, зникає разом із вузлом.

**Лічильник `removed`.** Тепер він рахує і декларації, і функції. Цикл зупиняється, коли раунд не видалив ні того, ні іншого. Тому один цикл обслуговує обидва завдання, і змінні, що стали мертвими після видалення функції, теж зникнуть у наступному раунді.

**Чому каскад працює сам.** У раунді 1 тіло `unused` ще в дереві, тож виклик `helper(1)` порахований, і `helper` вважається живим. Коли `unused` прибрали, раунд 2 рахує заново на меншому дереві, де `helper` уже без викликів.

Це випадок, який я згадувала раніше, і ми його перевіримо на практиці. Спочатку покажемо проблему, потім виправимо.

## У чому проблема
Checker кладе кожну лямбду не лише в дерево, а й у плоский список `tree.lambda_structs`. Лямбди, яких уже немає в дереві, треба прибрати зі списку `lambda_structs`. Для цього `UseCounter` запам'ятовує, які лямбди він реально зустрів під час обходу, а після циклу ми залишаємо в списку лише їх.

**1. У `UseCounter.__init__` додай один рядок:**
```python
        self.live_lambdas = set()
```

**2. У `UseCounter.walk` у гілці `LambdaNode` додай перший рядок:**
```python
        elif isinstance(n, LambdaNode):
            self.live_lambdas.add(id(n.struct))
            self.walk(n.decl)
            self.walk(n.body)
            return
```

**3. У `remove_unused` змінюй умову виходу:**
```python

            tree.lambda_structs = [s for s in tree.lambda_structs if id(s) in counter.live_lambdas]

```

## Чому це правильно

- **`live_lambdas` збирається під час тієї ж ходи, що й підрахунок.** Лямбда, яку обхід бачить у дереві, жива. Якщо її функцію видалили, обхід до неї не доходить.
- **Беремо `counter` останнього раунду.** Коли `removed == 0`, цей обхід ішов по вже остаточному дереві, тож `live_lambdas` точно відповідає тому, що лишилось.
- **Вкладені лямбди** теж знаходяться: гілка `LambdaNode` обходить `n.body`, де може бути інша `LambdaNode`.
- **Лямбди в member functions** теж знаходяться: структури лежать у `tree.structs`, а їхні `fns` обходяться через `children()`.
- **Без прапорця нічого не змінюється,** бо `remove_unused` просто не викликається.

# Task 3, крок 2: `run_tests.py` для `tests/opt`

Для цих тестів вимога інша, ніж для `ok` і `err`: вони мають проходити **в обох режимах**, і ще порівнюється дерево `.astc`. Тому `tests/opt` ганяємо завжди двічі, незалежно від того, з прапорцем ти запустила скрипт чи без.

## Правки

**1.** У `run_output_test` додай параметр `flags` і використай його:

## Що і чому

- **`[plain]` і `[opt]`.** Кожна програма з `tests/opt` проходить без прапорця і з ним, і обидва рази вивід порівнюється з одним `.expected`. Це і є «оптимізація не змінює, що друкує програма».
- **`.astc`** порівнюється з виводом `--remove-unused --ast-checked`. Це фіксує, що саме прохід видалив: якщо хтось пізніше зламає підрахунок, дерево зміниться і тест упаде.
- **`astc_path[:-5]`** відрізає `.astc` (5 символів), щоб знайти `.txt` поруч.
- **Існуючі глоби не чіпаємо.** `tests/*.txt`, `tests/ok` і `tests/err` не заходять у `tests/opt`, а шаблон `tests/**/*.ast` не збігається з `.astc`, тож нічого не порахується двічі.
- **Параметр `flags` за замовчуванням** лишає поведінку для `ok` і `err` такою, як була: прапорець береться з командного рядка.

```python
import glob
import subprocess
import sys

FLAGS = ["--remove-unused"] if "--remove-unused" in sys.argv else []
OUT_LL = "/tmp/run_tests_out.ll"


def run_output_test(txt_path, flags=None):
    if flags is None:
        flags = FLAGS
    exp_path = txt_path[:-4] + ".expected"
    try:
        with open(exp_path) as f:
            expected = f.read().strip()
    except FileNotFoundError:
        return None

    result = subprocess.run(
        ["python3", "compiler.py", *flags, txt_path, OUT_LL],
        capture_output=True, text=True
    )

    if result.returncode == 0:
        try:
            with open(txt_path[:-4] + ".in") as f:
                stdin_text = f.read()
        except FileNotFoundError:
            stdin_text = ""
        lli_result = subprocess.run(
            ["lli", OUT_LL],
            capture_output=True, text=True, input=stdin_text
        )
        actual = lli_result.stdout.strip()
    else:
        actual = result.stderr.strip()

    return actual == expected, actual, expected


def run_ast_test(ast_path):
    txt_path = ast_path[:-4] + ".txt"
    with open(ast_path) as f:
        expected = f.read().strip()

    result = subprocess.run(
        ["python3", "compiler.py", "--ast", txt_path],
        capture_output=True, text=True
    )
    actual = result.stdout.strip()

    return actual == expected, actual, expected


def run_astc_test(astc_path):
    txt_path = astc_path[:-5] + ".txt"
    with open(astc_path) as f:
        expected = f.read().strip()

    result = subprocess.run(
        ["python3", "compiler.py", "--remove-unused", "--ast-checked", txt_path],
        capture_output=True, text=True
    )
    actual = result.stdout.strip()

    return actual == expected, actual, expected


def report(path, ok, actual, expected, counters):
    if ok:
        counters["passed"] += 1
        print(f"PASS  {path}")
    else:
        counters["failed"] += 1
        print(f"FAIL  {path}")
        print(f"      expected: {expected!r}")
        print(f"      actual:   {actual!r}")


def main():
    counters = {"passed": 0, "failed": 0}

    programs = sorted(
        glob.glob("tests/*.txt")
        + glob.glob("tests/ok/*.txt")
        + glob.glob("tests/err/*.txt")
    )
    for path in programs:
        outcome = run_output_test(path)
        if outcome is None:
            continue
        report(path, *outcome, counters)

    for path in sorted(glob.glob("tests/**/*.ast", recursive=True)):
        report(path, *run_ast_test(path), counters)

    for path in sorted(glob.glob("tests/opt/*.txt")):
        for flags, label in (([], "plain"), (["--remove-unused"], "opt")):
            outcome = run_output_test(path, flags)
            if outcome is None:
                continue
            report(f"{path} [{label}]", *outcome, counters)

    for path in sorted(glob.glob("tests/opt/*.astc")):
        report(path, *run_astc_test(path), counters)

    print(f"\n{counters['passed']} passed, {counters['failed']} failed")
    sys.exit(1 if counters["failed"] else 0)


if __name__ == "__main__":
    main()
```

```markdown
## Optimizations

    python3 compiler.py --remove-unused input.txt output.ll
    python3 compiler.py --remove-unused --ast-checked input.txt

`--remove-unused` runs on the tree after the semantic pass has accepted the
program and before code generation. The flag may stand anywhere on the
command line; `--ast` still prints the parse tree.

**Variables.** A declaration is counted per declaration node (`id(decl)`),
not per name, so shadowing works: the outer `x` can go while the inner `x`
stays. A read is a use in an initialiser, the right side of `:=`, a
condition, an argument, `print`, `exit`, the start of a field chain, the
object of a member call, a capture list or a call of a callable object. The
target of `:=` is not a read. A dead declaration is removed together with
every assignment to it. A declaration whose initialiser contains a call or
`read()` stays, and so does an assignment with such a value together with
its variable. Parameters, fields and lambdas are never removed.

**Functions.** Calls of every global function are counted wherever they
stand: statements, other functions, member functions, lambda bodies. A
global function with no calls is removed with its body. Member functions
and lambdas stay. The lambda structs of removed functions are dropped from
`lambda_structs`, otherwise code generation would still emit their `call`.

**Iteration.** Each round counts again on the smaller tree and the loop
stops when a round removes nothing.

**Limits.** Counting cannot see a cycle: two functions that call only each
other, or a recursive function nobody else calls, stay. A variable that only
feeds itself (`k := k + 1` with nobody else reading `k`) stays, because the
right side reads it. Unused lambdas, struct types and member functions are
not removed.
```

Ці три ліміти закріплені тестами `mutual_recursion_stays` і `self_feeding`.

# Додаткове завдання: виклики без ефектів

## Що змінюється

У Task 1 ми зберігали кожне значення, у якому є будь-який виклик. Тепер значення зберігається, лише якщо воно містить `read()` або виклик функції з **ефектом**. Решта викликів (як `square(3)`) вважаються чистими, і декларація з ними може зникнути.

Функція має ефект, якщо виконується хоча б одне:
1. у її тілі є `print` або `read()`;
2. вона mutating member function (змінює об'єкт, на якому викликана);
3. вона може не повернутися: у тілі є `while` або вона викликає себе, прямо чи через інші функції;
4. вона викликає функцію з ефектом.

Правило 4 циклічне, тому множину рахуємо **fixpoint-ом**: беремо функції за правилами 1–3, потім додаємо їхніх викликачів, поки множина росте.

## Приклад з завдання

```
a{square(3)}, b{quiet(4)}, c{loud(5)}, exit 0
```

Ефект має тільки `loud` (є `print`). `quiet` викликає `square`, обидві чисті.

| Раунд | Що видаляється |
|---|---|
| 1 | `a` і `b` (виклики без ефекту, читань нуль); `c` лишається через `loud` |
| 2 | `quiet` (її єдиний виклик зник разом із `b`) |
| 3 | `square` (її єдиний виклик сидів у `quiet`) |
| 4 | нічого, зупинка |

У трасі очікую `removed 2`, `1`, `1`, `0`. Програма друкує `5` і дає `result 0`, як і до оптимізації.

## Що треба врахувати саме в твоєму дереві

- **Оголошення лямбди не виконує її тіла.** Тому при пошуку `print`, `while` і викликів у тілі функції `LambdaNode` пропускаємо. Тіло лямбди враховується, лише коли її викликають: це виклик `call`, який лежить в `lambda_structs`.
- **Виклик callable-об'єкта.** `add_k(5)` лишається `CallNode`, а справжній виклик у `node.sugar.fn`. Те саме для `s.scale(7)`, де у зовнішнього `MemberCallNode` атрибута `fn` немає. Тому функція `callee_of` дивиться спершу на `sugar`.
- **`mutating` є лише в `MemberFnNode`.** У глобального `FnNode` цього атрибута немає, тож перевіряємо тип перед зверненням.
- **Множину ефектів перераховуємо кожного раунду.** Тіла функцій змінюються, і зайвих припущень вона не повинна переносити.

# Крок 1: множина функцій з ефектом

## Код

Вставити в `compiler.py` одразу після функції `has_call_or_read` і перед `class UseCounter`:

```python
def callee_of(n):
    sugar = getattr(n, "sugar", None)
    if sugar is not None:
        return getattr(sugar, "fn", None)
    return getattr(n, "fn", None)


def has_effect(n, effects):
    if isinstance(n, ReadNode):
        return True
    if isinstance(n, (CallNode, MemberCallNode)) and callee_of(n) in effects:
        return True
    return any(has_effect(c, effects) for c in n.children())


def own_effect(n):
    if isinstance(n, LambdaNode):
        return False
    if isinstance(n, (PrintNode, ReadNode, WhileNode)):
        return True
    return any(own_effect(c) for c in n.children())


def collect_callees(n, out):
    if isinstance(n, LambdaNode):
        return
    if isinstance(n, (CallNode, MemberCallNode)):
        fn = callee_of(n)
        if fn is not None:
            out.add(fn)
    for c in n.children():
        collect_callees(c, out)


def all_functions(tree):
    fns = list(tree.functions)
    for st in tree.structs + tree.lambda_structs:
        fns += st.fns
    return fns


def reaches_itself(f, callees):
    seen = set()
    stack = list(callees[f])
    while stack:
        g = stack.pop()
        if g is f:
            return True
        if g in seen or g not in callees:
            continue
        seen.add(g)
        stack.extend(callees[g])
    return False


def effectful_fns(tree):
    fns = all_functions(tree)
    callees = {}
    effects = set()
    for f in fns:
        out = set()
        collect_callees(f.body, out)
        callees[f] = out
        if (isinstance(f, MemberFnNode) and f.mutating) or own_effect(f.body):
            effects.add(f)
    for f in fns:
        if reaches_itself(f, callees):
            effects.add(f)
    changed = True
    while changed:
        changed = False
        for f in fns:
            if f not in effects and callees[f] & effects:
                effects.add(f)
                changed = True
    return effects


def fn_label(f):
    owner = getattr(f, "owner", None)
    return f"{owner}.{f.name}" if owner else f.name
```

## Що тут і чому

- **`own_effect`** шукає правила 1 і 3 (частину про `while`): `print`, `read()` або `while` у тілі, не заходячи в оголошення лямбд.
- **`collect_callees`** будує граф викликів: для кожної функції множина функцій, які вона викликає. Він потрібен для рекурсії (правило 3) і для поширення ефекту на викликачів (правило 4).
- **`reaches_itself`** обходить цей граф і відповідає, чи можна дійти від функції до неї самої. Так ловимо і пряму рекурсію, і цикл через кілька функцій.
- **`effectful_fns`** збирає все: спочатку правила 1–2, потім рекурсія, потім цикл поширення до фіксованої точки.
- **`has_effect`** потрібна на кроці 2: вона замінить `has_call_or_read` і питатиме, чи значення містить `read()` або виклик функції з множини `effects`.
- **Ключі множини це самі вузли функцій.** `FnNode` не перевизначає `__eq__`, тож порівняння йде за ідентичністю.

# Крок 2: підключаємо множину ефектів до підрахунку

Тепер `UseCounter` замість «будь-який виклик» питає «є `read()` або виклик функції з ефектом». Окремого прапорця немає: за завданням це нова поведінка самого `--remove-unused`.

## Правки

**1.** Заміни клас `UseCounter` цілком. Змінено три місця: параметр `effects`, метод `observable` і два місця, де раніше стояв `has_call_or_read`.

```python
class UseCounter:
    def __init__(self, effects=None):
        self.effects = effects
        self.reads = {}
        self.decls = {}
        self.calls = {}
        self.fn_nodes = {}
        self.live_lambdas = set()

    def observable(self, n):
        if self.effects is None:
            return has_call_or_read(n)
        return has_effect(n, self.effects)

    def read(self, decl):
        if isinstance(decl, DeclNode):
            self.reads[id(decl)] = self.reads.get(id(decl), 0) + 1

    def walk(self, n):
        if isinstance(n, FnNode) and not isinstance(n, MemberFnNode):
            self.fn_nodes[id(n)] = n
            self.calls.setdefault(id(n), 0)
        if isinstance(n, DeclNode):
            self.decls[id(n)] = n
            self.reads.setdefault(id(n), 0)
            if any(self.observable(e) for e in n.inits):
                self.read(n)
        elif isinstance(n, AssignNode):
            if self.observable(n.value):
                self.read(n.decl)
        elif isinstance(n, (VarNode, MemberNode)):
            self.read(n.decl)
            return
        elif isinstance(n, LambdaNode):
            self.live_lambdas.add(id(n.struct))
            self.walk(n.decl)
            self.walk(n.body)
            return
        sugar = getattr(n, "sugar", None)
        if sugar is not None:
            self.walk(sugar)
            return
        if isinstance(n, CallNode) and n.this is None:
            self.calls[id(n.fn)] = self.calls.get(id(n.fn), 0) + 1
        for c in n.children():
            self.walk(c)

    def report(self):
        for d in sorted(self.decls.values(), key=lambda d: (d.line, d.col)):
            print(f"line {d.line}: {d.name} reads={self.reads[id(d)]}")
        for f in sorted(self.fn_nodes.values(), key=lambda f: (f.line, f.col)):
            print(f"line {f.line}: fn {f.name} calls={self.calls[id(f)]}")
```

**2.** У `remove_unused` одна рядкова правка: множина ефектів рахується на початку кожного раунду і передається в лічильник.

```python
def remove_unused(tree):
    rounds = 0
    while True:
        rounds += 1
        counter = UseCounter(effectful_fns(tree))
        counter.walk(tree)
        dead = {i for i, k in counter.reads.items() if k == 0}
        dead_fns = {id(f) for f in tree.functions if counter.calls.get(id(f), 0) == 0}
        pruner = Pruner(dead, dead_fns)
        pruner.prune(tree)
        if os.environ.get("OPT_TRACE"):
            print(f"round {rounds}: removed {pruner.removed}", file=sys.stderr)
        if pruner.removed == 0:
            tree.lambda_structs = [s for s in tree.lambda_structs if id(s) in counter.live_lambdas]
            return tree
```

## Що і чому

- **`effects=None` лишає стару поведінку.** Дебаг `OPT_DEBUG` викликає `UseCounter()` без аргументів, і йому досі підходить грубе правило. Для реального проходу множина передається завжди.
- **Множина перераховується щоразу.** Після видалення функції чи декларації тіла змінюються, а граф викликів теж. Стару множину переносити не можна.
- **Дві функції з одним і тим самим змістом `observable`.** Один виклик у `Decl` (ініціалізатор), другий в `Assign` (права частина): правила для них тепер однакові, як і вимагає завдання.
- **Ефект рахується лише для значення, яке ми могли б викинути.** Сам виклик, що стоїть у `exit` чи в умові, читає змінні й так, тож його ця логіка не зачіпає.

# Лишилась нотатка про пам'ять

Секція Optimizations у README описує поведінку без додаткового завдання, тому її потрібно оновити. Вимірювання `measure_free.py` ти ще не запускала, а від його виводу залежить останній абзац. Запусти зараз:

```bash
cat > measure_free.py <<'EOF'
import gc
import weakref
import compiler as c


def load(path):
    with open(path, "rb") as f:
        data = f.read()
    tree = c.Parser(c.lex(data)).parse_program()
    c.SemanticChecker().check(tree)
    return tree


def weak_decl(tree, name):
    for s in tree.statements:
        if isinstance(s, c.DeclNode) and s.name == name:
            return weakref.ref(s)


def weak_fn(tree, name):
    for f in tree.functions:
        if f.name == name:
            return weakref.ref(f)


def weak_lambda(tree, fn_name):
    for f in tree.functions:
        if f.name == fn_name:
            for s in f.body.statements:
                if isinstance(s, c.LambdaNode):
                    return weakref.ref(s)


def measure(label, path, pick):
    tree = load(path)
    ref = pick(tree)
    c.remove_unused(tree)
    right_after = ref() is None
    gc.collect()
    after_gc = ref() is None
    print(f"{label}: freed right after the pass: {right_after}; after gc.collect(): {after_gc}")


gc.disable()
measure("variable y", "tests/opt/warmup1.txt", lambda t: weak_decl(t, "y"))
measure("function unused", "tests/opt/fn_chain.txt", lambda t: weak_fn(t, "unused"))
measure("lambda inner", "tests/opt/lambda_in_dead_fn.txt", lambda t: weak_lambda(t, "unused"))
EOF
wc -l measure_free.py
python3 measure_free.py
```

Файл має мати 49 рядків. Скинь три рядки виводу. З ними я складу секцію для README: оновлений опис правила ефектів, ліміти (цикли, `k := k + 1`, що лямбди, структури та member functions не видаляються) і абзац про пам'ять з виміряними цифрами, а не з моїми припущеннями. Мій прогноз такий: змінна й функція звільняються одразу, лямбда лишається до `gc.collect()` через цикл посилань, але виводити це я буду тільки з твого виводу.
